# 京东读书

使用京东官方 Web 协议：阅读 API 为 `https://e.m.jd.com`，扫码会话由 `qr.m.jd.com` 和 `passport.jd.com` 兑换。不使用 App 私有接口。

## 能力与边界

| 功能 | 当前实现 |
| --- | --- |
| 登录 | 京东 App 扫码；远程管理的浏览器扩展授权。两者都在书架 API 校验成功后才保存新凭证，失败或取消保留原凭证 |
| 书架 | 拉取排序与分批详情；本地新增、删除通过同步上行。远端写操作本轮未实测 |
| 书城 | 搜索、榜单及其周期、分类筛选 |
| 阅读 | EPUB、TXT 网文章节目录与正文；受官方试读、购买和会员权限限制 |
| 进度 | 拉取、推送章节与全书比例；本地章节 HTML 不对应京东段落坐标，从章节起点恢复 |
| 笔记、统计 | 本地保存，不提供京东云端笔记、阅读时长同步 |
| 评论 | 本书源未接入京东书评、章评、段评及回复接口；本轮未研究这些入口，不推断官网不存在接口 |
| 离线 | 已缓存章节、本地进度、笔记与统计可用；未缓存正文、书城和同步需要联网 |

网页有会话不代表扩展已把会话交给设备。浏览器授权需要安装 `moon-cookie-storage` 并在远程管理页面完成握手。

### 扫码后的安全验证

官方扫码脚本 `login.qrcode.2024.js`（`0.0.24`）在 `returnCode=80` 时要求改用密码登录；`returnCode=0` 则继续访问返回的 `url`，并不保证安全验证已经结束。

插件始终先走完官方跳转，不因出现 `pin` 或 `thor` 就跳过下一步。跳到 `aq.jd.com/certified` 时明确报错，不把未验证的候选会话保存为登录成功。**当前尚未实现把原扫码会话的官方验证页转发到浏览器并在验证后续接登录**；既有浏览器扩展授权是独立的登录方式，不能替代此功能。

授权检查不能使用始终返回 HTTP 200 的 SPA 首页。每次授权生成新的签名书架检查地址，只有 JSON 的 `result_code=0` 才采集；设备收到会话后还会再次校验书架。验证期间不会覆盖原会话，浏览器授权成功后重建源实例。

## 主要接口

普通 API query 按参数名排序，以 `app=jdread-m`、毫秒时间戳 `tm`、设备 `uuid` 和路径计算双 MD5 签名。浏览器的 `client` 随平台变化；本插件使用 `pc`。

| 用途 | 方法、路径 | 参数与响应 | 登录 |
| --- | --- | --- | --- |
| 扫码 | GET `qr.m.jd.com/show`、`/check` | `appid=133`；每张码独立的 Cookie 与 token；确认后取得 ticket | 匿名扫码会话 |
| 兑换 | GET `passport.jd.com/uc/qrCodeTicketValidation` | `t`、`ReturnUrl`；检查 `returnCode`、响应 Cookie 和官方中转跳转 | 扫码 ticket |
| 会话校验、书架排序 | GET `/jdread/api/bookshelf/sort` | `data.book_ids[].ebook_id`；`result_code=3, message=NOT.LOGIN` 表示会话无效 | 是 |
| 书架详情 | GET `/jdread/api/ebooks/lite/<ids>` | 逗号分隔 ID，每批 18 本；`data` 为详情数组 | 是 |
| 书架上行 | POST `/jdread/api/bookshelf/book/sync` | `version`、`first_sync`、`items`；当前实现新增 `action=0`、删除 `action=1`，写入成功语义本轮未核对 | 是 |
| 搜索 | GET `/jdread/api/search/v2` | `keyword`、`page`、`page_size` | 不要求 |
| 榜单、分类 | GET `/jdread/api/rank/type`、`/rank/<kind>`、`/category` | 榜单周期 `period`、分类 `catid`、分页 | 不要求 |
| 详情、目录 | GET `/jdread/api/ebook/lite/<id>`、`/ebook/catalog/v2/<id>` | 目录 `index` 为行偏移，按 `has_more` 合并后续页 | 随内容权限 |
| 正文 | GET `/jdread/api/download/chapter/<id>` | EPUB 传 `indexes`，网文传 `type=1, ids`；`enc=1` 及 AES 参数。错误码 101 为不可下载，不写入成功缓存 | 随内容权限 |
| 进度 | POST `/jdread/api/marker/sync` | `ebook_id`、`format=1`；推送附带 `list` | 是 |

## 本地与账号行为

本地书库和文件为真相。用户新增、删除或推进度先在本地生效，联网后由同步推送；删除保留墓碑，远端确认后再清库。失败保留待同步状态。

退出登录先取消该源在飞任务、清凭证，再清该源本地书架、进度、笔记和缓存；不会把清库当作远端删书。退出会丢掉该源尚未同步的本地记录，确认框会说明。

候选登录校验不修改旧账号的过期状态。当前没有按稳定账号 ID 分隔多账号本地数据；切换到不同京东账号应先退出原账号，不应把重新授权当作多账号切换。

## 2026-11-07 发包对比

- 官方 Chrome 网页：书架排序、详情均为 HTTP 200、`result_code=0`；排序行含数字 `ebook_id`，本轮未出现缺失 ID。网页使用 `client=mac`，不传 `ov`。
- 独立 KOReader 模拟器：原生 Turbo 发出的签名书架请求到达京东，匿名响应为 HTTP 200、`result_code=3`、`NOT.LOGIN`，未复现 URL 解析失败。
- 将模拟器生成的同一个 URL 交给浏览器发送：网页已有登录态时成功，不带会话时返回同样的 `NOT.LOGIN`。因此 `client=pc`、`ov=1.0` 及当前签名方式在这次比较中均被接受，没有据此修改协议参数。
- 模拟器的无效测试会话曾同时满足“界面已登录”和 `configured()`，但实际 API 拒绝。已改为扫码兑换后校验书架再报成功；用模拟 ticket 兑换和真实京东书架请求验证，失败不覆盖旧凭证。这不是完整扫码实测。
- 本机浏览器授权页面未检测到扩展，本轮未完成扩展回传，也没有在模拟器验证真实账号的完整书架同步。未读取或导出浏览器凭证，未修改远端书架或进度。
- 官方公开脚本核对了扫码风控码 80 和成功后的强制跳转。安全验证跳转时拒绝假成功、候选 Cookie 和票据检查地址绑定均有离线回归。浏览器可打开不带认证参数的 `aq.jd.com/certified/index`，但该页面不加载完整验证模块；curl 在本机超时。未取得真实认证会话，未故意触发账号风控，也未实现或实测验证码提交及原扫码会话续接。
- 用户历史日志中的 `Invalid URL provided.` 缺少失败请求地址和响应结构，仍不能确认是书架异常 ID 还是其他设备侧问题。已有缺失 ID 生成 `table: 0x…` 地址的缺陷已修复，异常记录会明确失败而不是拿残缺快照对账。

本轮只验证上述书架读取、参数兼容性和无效登录拒绝路径。目录、正文、已购内容、书城后续页、评论及远端增删／进度写入均不算本轮实测。
