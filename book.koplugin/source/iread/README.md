# iRead

源 ID：`iread`。官网：<https://iread.ankio.net>。最近核对：2026-11-07。

这是 iRead「爱阅读」服务，不是掌阅 `ireader`。iRead 在服务端执行用户配置的阅读书源规则；月读只调用 iRead 的 Web 接口，不直接移植各上游网站或 App 的私有协议。

## 能做什么

- 使用个人 Token、手动粘贴电脑网页 Cookie，或通过月读浏览器扩展导入 Cookie。凭据经账号接口校验成功后才保存；Token 与 Cookie 互斥，校验可取消。
- 未登录时搜索、浏览服务端提供的公共书源；登录后使用账号配置的书源。发现分类从服务端动态获取，「换一批书源」重新取规则。
- 对包含 `{{page}}` 的发现 URL 按页取书，按调用方 limit 聚合、去重；中间页失败或搜索轮询超时会报错，不把不完整结果当成功。
- 拉取个人书架；本地新增和删除先立即生效，随后同步收藏或取消收藏。收藏接口是开关，写前查成员关系，写后重新读书架确认。
- 读取目录、服务端正常返回的文字正文，并复用月读的章节预取、章节缓存、全本缓存和离线打开机制。
- 拉取和上传章节级阅读位置。上传后重新读书架核对章节序号与章内位置；确认失败保留本地脏进度。
- 搜索和书架返回的原始书记录随本地书籍元数据保存；重启或书城缓存命中后，仍能为加架和目录请求提供必要参数。

## 能力边界

| 项目 | 当前状态 |
|---|---|
| 原生密码／扫码登录 | 插件未接入。网站账号登录交由官方网页完成，月读导入 Token 或 Cookie；不能把网站没有源内密码表单说成账号系统不支持密码或扫码 |
| 同账号续期／直接换账号 | 尚未核实可用的稳定账号标识，不用昵称或凭据变化推断账号。已有凭据时拒绝替换成另一份凭据；同账号换 Token／换 Cookie 也须先退出旧登录 |
| 漫画和带图片的正文 | 官网阅读脚本有漫画模式，插件尚未接入图片落地。明确报错，不剥掉图片后把空正文缓存成成功 |
| 书评／章评／段评／回复 | 本次检查的公开 Web 阅读脚本未找到可验证接口，插件未提供；不据此断言上游网站或 App 都没有评论 |
| 笔记／阅读统计云同步 | 本源未实现对应接口。划线、笔记和阅读统计保存在本机，不代表已上传 iRead |
| 已购／未购正文 | 权限和可用性由 iRead 配置的上游规则及登录状态决定；本次没有真实已购账号验证，不承诺所有付费书源均可读，不绕过购买或验证码 |
| 任意发现规则分页 | 只替换已核实的 `{{page}}` 占位符，不在设备上执行规则内 JavaScript。其他模板不自行猜参数；没有该占位符的入口只取一批 |
| 任意上游书源稳定可用 | 不能保证。iRead 返回业务成功但正文为空、上游失效或规则解析失败时，月读报错且不生成成功缓存 |

**更换凭据前先关书，再从设置退出 iRead。** 退出确认会清除本机该源的书架、进度、笔记和缓存，包括尚未同步的记录；不写删书墓碑，不会借清库删除远端书架。当前没有按账号分别保留本地数据，也不会静默清库后自动换号。

## 登录方法

在「设置 → 书库 → 账号 → iRead」中：

1. 个人 Token：用电脑登录 <https://iread.ankio.net/user/token>，创建 Token，点「iRead 账号」粘贴。接受裸 Token 或带 `Bearer ` 前缀的文本，不保存密码。
2. 手动 Cookie：在电脑官网已登录请求的请求标头中复制 Cookie，点「粘贴 Cookie」。粘贴与扩展导入均先验证，不覆盖验证失败或取消前的旧凭据。
3. 浏览器扩展：沿月读「远程管理 → 浏览器登录」的现有授权流程导入。只保留 `iread.ankio.net` 和有效父域 `ankio.net` 的 Cookie，不采纳兄弟站点的 Cookie。

登录失效与临时网络错误分别处理。旧凭据请求迟到不能改变新登录态，两个登录校验竞态时不允许后到响应覆盖先保存的凭据。浏览器扩展的完整回传和真实账号登录未在本次独立环境实测。

## Web 协议与接口概览

接口相对 `https://iread.ankio.net`，采用 `POST` 表单和 `X-Requested-With: XMLHttpRequest`，响应为 `{ code, msg, data }`，业务码 `200` 表示该次请求成功。账号请求携带个人 Token 的 `Authorization: Bearer <token>` 或本站 Cookie；游客请求不携带账号凭据。所有 Token、Cookie 和书籍 ID 都是运行时值，不应写进文档或日志。

| 用途 | 方法与路径 | 参数、响应与登录要求 |
|---|---|---|
| 账号校验 | `POST /user/home` | 读取账号对象并核对非空 `nickname`。本次匿名请求为 HTTP 200、业务码 401，`data` 是官方授权地址，不是有效账号 |
| 个人书架 | `POST /book/list` | 原始书记录数组，需要账号。匿名也可能返回业务码 200 的空数组，不能据此认为账号有效；空架另外调用账号接口校验 |
| 目录 | `POST /book/chapters` | 书记录整行表单；返回有序章节对象，包含 `url/title/index/isVolume/isVip/isPay` 等。本次游客目录读取通过 |
| 章节正文 | `POST /book/chapter` | `book` 和 `chapter` 是原始对象的 JSON 字符串，`index` 为零基章序号；正常正文读取 `data.content`。空值、坏响应和站点错误不能落成功缓存 |
| 搜索／发现提交 | `POST /book/search` | 搜索为 `bookname`；发现为 `type=explore/id/url`；返回 `task/total`。可匿名使用，已登录时使用账号配置的规则 |
| 搜索结果轮询 | `POST /book/search/result` | `task`；返回增量 `result[]` 与待完成任务数 `remaining`。沿用提交响应的会话 Cookie；每 2 秒轮询，最多 30 次，超限失败 |
| 发现入口 | `POST /kindle/exploreRules` | 返回服务端当次选出的书源规则，`id/bookSourceName/exploreUrl`；标题项可用空 URL 分组，非空 URL 才可点击。可匿名使用 |
| 收藏开关 | `POST /book/favourite` | 书记录整行，需要账号；官网读取 `data.favourite` 显示最终状态。插件写前查架、写后回读，避免重试把新增变成删除或反过来 |
| 上传阅读位置 | `POST /book/process` | 新鲜书记录整行，改 `durChapterIndex/durChapterPos/durChapterTitle/durChapterTime`；需要账号。必须回读核对，不能只凭业务码确认 |

书记录身份保持为书名：服务端的 `bookUrl/sourceId` 可随换源变化，不改月读已保存的 `stable_id`。章节 uid 保留原始零基序号，目录原始章节 JSON 保存在 `raw`；不重命名已有章节路径，也不强制丢弃旧目录缓存。

官网的 `durChapterPos` 是其阅读器的页位置或漫画滚动位置，不是字符偏移。月读目前只同步到章：回读的全书比例按章序号估算；在同一章上传时保留远端章内位置，换章时置零，不伪造两套排版之间的精确章内比例。

KOReader 的 LuaJSON 默认把 JSON `null` 解为函数哨兵。本源解码使用其 `simple` 模式将空值解为 nil；旧元数据中遗留的空值哨兵不参与表单编码，避免把函数地址当字段值发给服务器。

## 本地、同步与离线

- 本地 sqlite 和文件是唯一真相。未联网时加入书库、删除、保存阅读位置和笔记仍先在本地完成；没有账号时不发个人书架或进度写请求。
- 新增书籍的源记录从搜索／发现结果保存；旧版本的本地新加书若缺少这些记录，需要重新搜索一次，不伪造上行参数。
- 删除复用公共三段式：清本地缓存、标墓碑、下次同步推远端删除。远端仍在架、回读失败或网络失败时保留墓碑；确认删除后才清除依附数据。
- 全量书架同步复用公共 `source.shelf`：先推删、拉远端、推本地新增，必要时重新拉架再对账；`dirty_only` 只推本地改动。空远端快照按公共防误删规则不清架。
- 进度写入前拉新鲜书记录，避免用陈旧整行覆盖服务器元数据；确认不一致则保留脏记录，由现有推脏任务重试。
- 已有目录和成功缓存的章节沿公共阅读机制离线复用。未缓存正文、搜索和发现依赖网络，离线立即失败；不使用阻塞 DNS 的 `isOnline`。
