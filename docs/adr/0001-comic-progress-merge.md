# 漫画进度：服务端做中转，合并在客户端

漫画进度以 Kavita 的 `pageNum`（0-based 图像序号，`== pages` 表示读完）为唯一单位，且只有「同一章 + 页数相同」
才可比。Kavita 的 `POST /api/Reader/progress` 是无条件覆盖、不做「更靠后优先」，所以合并规则只能落在客户端：

- **有未推送的本机阅读** → 按位置合并，**读得更远的赢**（离线读 80% 不会被在线 31% 覆盖）。
- **没有未推送阅读** → 按服务端 `lastModifiedUtc` 采纳（别人写过就以服务端为准，方向不限）。服务端时间戳
  由服务器生成，跨设备时钟不影响它。
- **回翻**（读者故意往回读）由 `base_page` / `base_ts`（本机最后一次确认到的服务端值与时间戳）判定：
  只有「本机位置低于已确认位置」且「服务端自那以后没动过」才允许把位置写低，否则以更靠后的一方为准。

## Considered Options

- **服务端权威**：离线读的进度会在回连时被更旧的服务端值覆盖（用户实际踩到过）。
- **本机 journal 权威**（改造前）：跨设备各自为政，A 设备读过的位置 B 设备永远看不到。
- **纯取最大**：无法表达「回翻」，回退后的位置永远丢失（用户明确要「回翻后能跳到 35%」）。

## Consequences

- 每章要多记 `base_page` / `base_ts`；写入前要读一次服务端（开书一次、关书一次，阅读中零额外请求）。
- 漫画按图像序号比较，与 epub 的 spine 口径**不可换算**；`pages` 不同的两端禁止按页合并。
- 并发「本机离线前进」与「别人在线回退」无法用因果区分，按取更靠后兜底。
- 系列聚合（容器行）统一用卷级聚合；服务端 `pagesRead/pages` 只在目录不可得时兜底。
